## 概要

エージェントに多数のツールを直接呼び出させる従来方式は、ツール定義がコンテキストウィンドウを圧迫し、中間結果がモデルを何度も往復することでレイテンシとコストが膨らむ問題がある。『コードモード』は各ツールをサンドボックス内の関数として公開し、モデルにループや条件分岐を含む1本のプログラムを書かせることで、往復回数を減らし最終出力だけを返す設計パターンである。この記事はコードモードが有効な場面と、サンドボックス化・デバッグ面でのトレードオフを解説する。

## 設計のポイント

- 個々のツールを直接LLMに呼ばせず、サンドボックス内の関数として公開し、モデルに1本のプログラムを書かせて一括実行する
- search/executeのような汎用ツールへの集約だけでは往復回数の問題は解決しないため、コード実行環境を介した合成が必要になる
- 個人情報のマスキングのように『誰も用意していないツール』をモデル自身がコードとして書けるようにする
- 長時間タスクではコンテキストウィンドウに流れ込むトークン量を最小化する設計がレイテンシとコストを支配する

## 使いどころ

- 接続先ツール（MCPサーバーなど）が多く、ツール定義だけでコンテキストが圧迫されるエージェント
- 大量データを1件ずつモデルに読み書きさせるとコストと誤り率が跳ね上がる長時間タスク（例: データの一括加工・マスキング）
- 多数回のツール往復による遅延とAPIコストが問題になっているエージェントハーネスの見直し
